# 研究生生存栈 01｜学会 6 个 Git 概念，剩下的交给 AI

你电脑里有没有这些东西：

`论文最终版.docx`

`论文最终版2.docx`

`代码_能跑.py`

`代码_改之前能跑.py`

项目小的时候，这么保存还能撑住。等项目里有几十个文件，再让 Cursor、Codex 之类的 AI 一次修改十几个文件，很快就会出现一个问题。

**昨天那个还能跑的版本，到底去哪了？**

这一篇只解决一件事：让你理解 Git、GitHub、Gitee 里最常用的几个概念，然后把具体操作交给 AI。

## Git 是项目时间线

Git 可以理解成项目的版本记录系统。

今天完成 Baseline，明天加入新的 Loss，后天让 AI 重构代码。每完成一次有意义的修改，就保存一个版本节点。

这样 AI 改坏代码时，你至少知道改了什么，也知道可以回到哪里。

**AI 可以大胆修改，Git 负责让修改有记录。**

## GitHub 和 Gitee 放在哪里

GitHub 和 Gitee 都可以存放远程 Git 仓库。

GitHub 的国际开源生态更丰富，很多科研代码和 AI 项目首先发布在那里。中国大陆不同网络环境下，GitHub 的网页访问、Clone、Pull、Push 体验可能有波动。

Gitee 在国内网络环境下通常更直接，适合刚开始建立自己的项目管理习惯。

所以你只需要先记住这个关系：

```
你的电脑
   ↓
  Git
   ↓
GitHub / Gitee
```

真正需要掌握的是 Git 的项目管理逻辑。远程仓库可以根据网络环境和合作需求选择。

## 只记住 6 个词

**Repository**

仓库。可以理解成一个被 Git 管理起来的项目。

**Commit**

提交。给当前项目保存一个带说明的版本节点。

**Clone**

克隆。第一次把远程仓库完整拿到这台电脑。

**Push**

推送。把本地已经提交的修改同步到远程仓库。

**Pull**

拉取。把远程仓库里的最新内容同步到当前电脑。

**Branch**

分支。从当前稳定版本拉出一条新的实验路线，适合尝试风险较大的新方法。

## 建一个标准科研仓库

我把科研项目目录提前做成了一个模板。

```
research-project/
├── README.md
├── AGENTS.md
├── .gitignore
├── paper/
│   ├── main.tex
│   ├── references.bib
│   ├── sections/
│   └── figures/
├── src/
├── scripts/
├── data/
│   ├── raw/
│   └── processed/
├── configs/
├── results/
├── outputs/
└── docs/
```

其中 `paper/` 已经预制 Elsevier `elsarticle` 单栏论文结构，图件默认按约 5 in 宽度准备。

`AGENTS.md` 则是给 AI 看的项目说明书。它会告诉 AI 哪些目录可以改，哪些数据不能碰，什么时候必须先汇报再执行。

## 创建仓库后，把地址发给 AI

在 GitHub 或 Gitee 创建一个空仓库后，你会得到一个仓库地址。

接下来可以直接对 AI 说：

```
这是我的科研项目仓库：

[仓库地址]

请克隆到当前工作目录。
先阅读 README.md 和 AGENTS.md，
告诉我项目结构和当前状态。
暂时不要修改任何文件。
```

第一次把项目拿到电脑上，这个动作叫 Clone。

以后每天开始工作，可以说：

```
先检查当前 Git 状态，
再拉取远程最新版本。

如果存在冲突，先告诉我冲突在哪里。
```

AI 修改完成后：

```
检查本次修改。

告诉我：
1. 修改了哪些文件
2. 每个文件改了什么
3. 是否存在明显风险

暂时不要提交。
```

确认没有问题后：

```
提交本次修改并推送到远程仓库。

提交信息写清楚这次完成了什么。
```

换到另一台电脑时，只需要让 AI 先 Pull，再继续工作。

## AI 改坏了怎么办

可以直接说：

```
检查当前 Git 状态和最近提交历史。

告诉我有哪些恢复方案，
以及每种方案会影响哪些文件。

先不要执行恢复。
```

这一句里的“先不要执行”很重要。

碰到删除分支、覆盖文件、回滚、强制推送这类操作，先让 AI 解释影响，再决定要不要执行。

## 以后你只需要会说人话

实验室电脑做完一部分工作，让 AI Commit 并 Push。

回到自己的电脑，让 AI Pull 最新版本。

想到一个风险较大的新方法，让 AI 新建 Branch。

AI 改坏代码，让它检查 Git 历史并给出恢复方案。

你真正需要掌握的是这些动作分别意味着什么。

命令本身，可以交给 AI。
