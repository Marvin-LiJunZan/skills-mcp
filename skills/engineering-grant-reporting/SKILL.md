# 工程科研课题申报与十卷册合规归档专精技能 (Engineering Grant Reporting)

本技能专为**企业重大科技攻关项目、工程横向研发课题、央企科技创新计划（如中铁/中建/中交等）以及企业研发费用加计扣除专项归档**打造。

技能整合了高规格工程技术叙事标准（彻底去除AI味与心虚防御性写作）、财务RD辅助账穿透式勾稽核验体系，以及完整的标准 Word / Excel 实战模版库，支持一键分发、开箱即用。

---

## 一、何时触发本技能 (Triggers)

当用户提出以下任一需求或类似指令时，自动激活本技能：
- “**课题申报 / 横向课题立项**”：撰写或修改企业科研项目立项申报书、计划书、合同书。
- “**中期检查 / 进展汇报**”：编制科技计划项目进展情况表、中期自查报告、阶段成果总结。
- “**结题验收 / 成果汇编**”：编制结题验收申请表、结题验收报告、成果佐证汇编、效益评价表。
- “**十卷册归档 / 补件核查**”：按照国家高企认定、企业技术中心评审与税务稽查要求整理10大卷册。
- “**财务辅助账与工时分配**”：核对RD科目金额、编制研发人员工时分摊表、剔除跨期与非研发开支。
- “**工程材料去AI味**”：消除申报材料中空泛套话，改用实测数据、公差与规范工程语调。

## 三、核心执行规范与避坑铁律

在协助用户起草、审查或修改课题材料时，必须严格执行以下规则：

### 1. 历史混淆数据绝对防错（避坑第一条）
- **决议表中“26”的定义**：历史计划汇总表中出现的数字“26”是**专家评审得分**，绝对禁止将“26”推断为“研发团队共26人”！所有人员名单必须以实际签认的花名册及个税申报为准。
- **双计划版本差异**：若存在“股份公司申报版（如460万、3专题）”与“集团正式批复版（如1228万、6专题）”，必须明确正式立项文件以**最终正式批复的批件与合同**为唯一基准，严禁两版数字相互混淆。

### 2. 工程学术“去AI味”与反防御性写作法则
- **拒绝心虚式自我审查**：严禁写“由于试验条件受限……”、“本模型仅作初步探索，可能存在不确定性”等推脱词。工程发布会应确立明确的技术适用边界与物理置信度。
- **拒绝宏大虚假套话**：严禁出现“显著提升”、“具有极其重大的历史意义”、“奠定了不可磨灭的坚实基础”。
- **仿真 vs 实测严格分离**：计算机有限元分析（ABAQUS/ANSYS）必须明确标注为“仿真模拟”，现场传感器光纤监测、超声波探伤必须注明“实体工程原位实测”，并对比两者之间的相对偏差。
- **以工程技术量化指标代替形容词**：例如“大跨度悬挑预拼装均方根误差 RMSE ≤ 0.5 mm”、“钢管混凝土超声探伤空洞检出率 ≥ 95%”。

### 3. 财务预算四级严密勾稽
- **单价 × 数量 = 合计**：杜绝明细乘积与合计数不符的低级计算错误。
- **明细之和 = 章节总额**：子项加总必须与总预算 100% 吻合。
- **剥离非研发支出**：建筑业协会会费、企业LEED认证咨询费、常规工程资料承包款，以及跨年度发放的既往奖金，必须从研发辅助账中予以剔除或单列说明。
- **委托研发合规认定**：委外开发必须有《技术开发合同》以及科技主管部门签发的《技术合同认定登记证明》，按 80% 计入加计扣除。

### 4. 知识产权时间线判定
- **申请日必须在立项期内**：课题立项日前已申请或授权的专利（如2022年申请），只能列为“前期技术基础”，不得包装为课题新增产出成果。
- **精确填写专利号**：必须带完整校验位（例如 `ZL 2025 1 0598192.9`），杜绝错号漏号。

## 四、十卷册闭环归档标准清单

协助整理项目归档时，必须按以下 10 大标准卷册核查完整性：
- **01 计划书**：盖章立项申报表 + 正式课题合同书/任务书。
- **02 决议文件**：集团年度科研计划下达通知红头文件及汇总附表。
- **03 机构与人员**：专门研发机构编制文件 + 研发人员名单 + 逐月个税申报单。
- **04 费用分配说明**：签章分配说明 + 逐月工时分配表 + 仪器设备折旧摊销记录。
- **05 辅助账汇总**：RD18辅助账逐笔明细账 + 多维汇总表 + 财税核减说明。
- **06 过程佐证**：试验采集原始记录 + 激光扫描点云 + 软件算法代码 + 中期检查材料。
- **07 成果佐证**：六专题研究总报告 + 专利证书 + 验收报告 + 工程应用效益证明。
- **08 委外合同与登记**：合作研发合同 + 省级技术合同认定登记证明 + 交付验收单。
- **09 政府科研任务**：政府科技项目任务书（若无则出具企业自筹课题说明）。
- **10 过程归档工具**：可编辑Word/Excel包 + 审查核验脚本 + 排版样式工具。

## 五、自动化工具与脚本调用

本技能在 `scripts/` 目录下提供了两个自动化工具：
1. **`audit_grant_consistency.py`**：
   - 快速审查指定 Word 文档中的 AI 套话、防御性措辞、专利号格式及“26人”等典型历史错误。
   - 调用命令：`python scripts/audit_grant_consistency.py <文件路径.docx>`
2. **`docx_table_formatter.py`**：
   - 快速将文档中的表格批量转换为学术出版标准三线表（Top/Header-bottom/Bottom），统一中西文字体（仿宋/Times New Roman）。

## 六、分发与团队共享指南

将本文件夹（`engineering-grant-reporting/`）打包或直接发送给项目团队成员即可使用：
- **在 Claude Code 中使用**：放置于项目目录 `.claude/skills/engineering-grant-reporting/` 或全局 `~/.claude/skills/`。
- **在 Antigravity / Gemini CLI 中使用**：放置于 `~/.gemini/config/skills/engineering-grant-reporting/` 或当前工作区 `skills_mcp/skills/`。
- **在 Cursor / VSCode 中使用**：将 `references/` 中的规范直接作为项目规则引入。
- **非 AI 团队成员直接使用**：直接双击打开 `templates/word/` 和 `templates/excel/` 中的模板进行填报与核对。
