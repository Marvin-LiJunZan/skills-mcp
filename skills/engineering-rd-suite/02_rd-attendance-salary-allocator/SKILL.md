# 研发费用人工费考勤表与薪酬分摊表自动化编排技能 (RD Attendance & Salary Allocator)

本技能专为**工程科研课题、央企科技计划（中铁/中建/中交等）横向项目、企业研发费用税前加计扣除专项申报及高企认定十卷册归档**打造。彻底解决传统手工编排中工时率失真、周末与法定节假日倒挂、跨期薪酬底表错位、公式死数断档等核心财税审计痛点。

## 一、何时触发本技能 (Triggers)

当用户提出以下任一需求或出现相关指令时，自动激活本技能：
- “**研发考勤表 / 研发人员考勤打点**”：生成研发项目月度出勤、科研打点工时表。
- “**职工薪酬分配表 / 人工费分摊明细表**”：提取真实工资与社保公积金，按工时率分摊至各研发课题。
- “**批量生成考勤与分摊表**”：针对 2022～2025 全周期各季度自动批量排班核算。
- “**基于法定金额倒推配平工时**”：根据季度汇总表中的法定研究人员费金额，反向求解优化各月考勤天数与科研打点工时。
- “**十卷册人工费归档整理**”：规整第 03 卷研发人员名单、第 04 卷费用分配表与第 05 卷辅助账的一致性。

## 二、七大财务与审计合规铁律 (Accounting & Audit Principles)

1. **考勤周期锁定**：统计周期严格固定为**上月 21 日至当月 20 日**（例如 1 月考勤周期为上年 12月21日～当年 1月20日；2 月考勤周期为当年 1月21日～2月20日）。
2. **多课题工时率硬约束**：一人兼任多个在研课题时，单人当期在所有课题中的**工时率累计总和严禁超过 100%**。
3. **真实月度穿透取数**：基数必须从季度汇总表下属的**独立月度薪酬子表（1/2/3月）**提取，严禁直接抓取季度合计值。
4. **全动态公式联动**：
   - 考勤天数：`=COUNT(D5:AH5)`（动态匹配结束列）
   - 科研天数：`=SUM(D6:AH6)/8`（纯公式无 ROUND 截断，单元格格式保留 2 位小数 `0.00_ `）
   - 工时率：`=AI6/AI5`（科研天数 / 出勤天数）
   - 分摊表联动：C 列引用考勤天数，D 列引用工时率，右侧金额严格以 `=基数 * $D5` 计算，合计行以 `=SUM(...)` 汇总。
5. **科研工时面额限定**：单日科研打点只能采用 **`8`、`4`、`2`、`1`、`0.5`** 这 5 种标准工时面额拆分拼凑，严禁随机无序小数。
6. **团队排班跟随领导**：优先排定课题负责人的科研日期；项目组成员的科研日期优先在课题负责人的科研日内挑选，重合率达 **100%**。
7. **法定研究费不可变与逆向优化倒推配平准则（2026-10 最新核心规则）**：
   - **法定金额为刚性基准**：原始季度汇总表中的**法定研究人员费总额（如 R19）及各人员对应的法定研究费**是申报税前加计扣除与账面入账的唯一基准，**绝对不可更改**。
   - **三月分摊合计必须严格配平**：生成的 3 张月度分摊表合计行（X16 单元格）之和，必须严格等于该法定研究人员费（差额控制在 $\le 0.05$ 元的微小分钱舍入内）。
   - **考勤符号与工时逆向倒推**：考勤打点（`8`、`/`、`-` 及空白单元格）完全由该法定研究人员费**通过运筹优化算法反向倒推生成**。当额定工时无法严格配平时，优先通过将无科研任务的工作日留空（置为空白单元格）或适度微调出勤天数实现分钱级精准配平。

## 三、通用项目适配规范：【静态不变】与【动态变动】审核矩阵

为了确保算法适用于**任何不同项目、不同课题负责人、不同季度表格**，严禁死写行列号，必须严格执行以下审核矩阵：

| 维度 | 要素类别 | 规则定义与取值逻辑 |
| :--- | :--- | :--- |
| **静态不变项** | 汇总表 Sheet 0 列定位 | D 列固定为课题负责人姓名，E 列固定为课题合同编号/项目编号 |
| **静态不变项** | 入账明细表列对结构 | 课题信息必然呈“成对”列出现：第 $k$ 列为课题工时率，紧邻的第 $k+1$ 列必为该课题研究人员费 |
| **静态不变项** | 表头与签署格式 | 考勤表 A1 居中主标题；负责人姓名必须置顶排在第 1 行（序号 1）；底部签名栏保持留白供人工打印手签 |
| **静态不变项** | 考勤统计周期 | 严格固定为上月 21 日至当月 20 日，春节放假严格归入 2 月份考勤周期 |
| **静态不变项** | 分摊表勾稽公式体系 | C 列 `='考勤表'!AI`，D 列 `='考勤表'!AJ`，分摊额 `=Base * $D`，合计列 `=SUM(...)` |
| **动态变动项** | 课题列对位置 ($k, k+1$) | **严禁写死 R 列**！不同课题因立项先后在各列浮动（如 2022Q2 为 Q/R 列，2024Q4 为 AA/AB 列），必须通过课题编号（如 `21-B-02`）或课题名称关键字全表扫描定位 |
| **动态变动项** | 负责人所在行号 | 汇总表 Sheet 0 中不同课题负责人分布在第 5～30 行不等，必须通过项目编号/名称动态匹配定位行号 |
| **动态变动项** | 明细表姓名列 | 2022～2024Q3 姓名列在第 1 列（B列），2024Q4 与 2025Q1 姓名列在第 3 列（D列），需动态查找“姓名”字样定位 |
| **动态变动项** | 项目成员名单与人数 | 随季度动态变动（5～11 人不等）。支持**季度中途入职或离职人员**（即某月份薪酬为 0 时，自动退化为有效在职月份子空间求解并平衡总额） |
| **动态变动项** | 日历天数与结束列 | 周期天数为 28～31 天，结束列动态适配于 AE 至 AH，统计列相应动态顺延至 AI、AJ |
| **动态变动项** | 薪酬列数自适应 | 自动识别是否含“4.企业年金/其他”（无年金 24 列，有年金 26 列），动态生成分摊计算公式 |

## 四、逆向求解运筹优化数学模型 (Mathematical Optimization Formulation)

将考勤打点与工时分配转化为**两级混合整数规划（MINLP/MILP）与广义多重背包问题**：

### 1. 优化模型形式化
对于人员 $i$，已知法定目标金额 $R_i^{\text{target}}$ 及 3 个月的薪酬基数 $B_m$：

$$\min_{A, H} \quad \mathcal{J} = \lambda_1 \cdot \left| \sum_{m=1}^3 \left( B_m \cdot \frac{H_m}{8 A_m} \right) - R_i^{\text{target}} \right| + \lambda_2 \sum_{m=1}^3 |A_m - W_m| + \lambda_3 \mathcal{P}_{\text{alignment}}$$

约束条件：
1. $A_m \in [W_m - 2, \; W_m + 2]$（出勤天数微调窗口）
2. $H_m = \sum_d h_{m, d}$，其中 $h_{m, d} \in \{0, 0.5, 1, 2, 4, 8\}$
3. $h_{m, d} \le 8 \cdot x_{m, d}$（不出勤不可填工时）
4. 若某月 $B_m = 0$（离职或未入职），该月自动约束 $H_m = 0, A_m = W_m$。

### 2. 两级分层解耦求解架构 (Hierarchical Decoupling)
- **Level 1（宏观配平）**：以有效月度薪酬基数对 $R_i^{\text{target}}$ 进行加权估算有效工时率，在 $0.5\mathbb{Z}$ 网格上离散搜索最优月度工时组合 $(H_1^*, H_2^*, H_3^*)$ 与出勤天数 $(A_1^*, A_2^*, A_3^*)$，将差额压缩至分钱级。
- **Level 2（微观贪心找零与日历投射）**：将最优月工时 $H^*$ 采用硬币找零法贪心分解为 `[8, 4, 2, 1, 0.5]` 标准面额序列，优先对齐负责人的科研日；出勤天数缩减时，优先将无科研任务的工作日设为空白单元格。

## 五、排班与日历特殊规则 (Calendar & Holiday Protocols)

- **公司春节特批假期**：
  - **除夕至正月初十（含两端）全员放假**，公司特批假期优先级**绝对高于国家周末调休上班**。
  - 例如 2024 年春节（2月9日～2月19日）全员休假，包含在 2 月考勤周期（1月21日～2月20日）内，2月18日（周日调休）亦休假。
- **打点标记字符**：
  - 出勤工作日：数字 `8`
  - 周末双休日：斜杠 `/`
  - 法定节假日与特批假期：连字符 `-`
  - 未出勤/调减出勤日：空白单元格（`None`）
  - 考勤表底部签名栏留白供打印后手签：`项目/课题负责人：             制表人：`

## 六、尾差末月公式平账规范 (Tail-Balancing & Zero-Diff Smoothing Protocol)

### 1. 尾差产生机理
- **离散工时与分钱不可除尽**：科研打点单日工时限定采用 5 种标准离散面额（`8, 4, 2, 1, 0.5` 小时），出勤天数 $A_m$ 为整数，计算所得的工时率 $D_m = \frac{H_m}{8 A_m}$ 为特定有理数，不可能除尽所有的分钱金额。
- **Excel 浮点乘积与四舍五入截断**：每个月份的应发工资、社保、公积金基数乘以工时率后保留 2 位小数，3 个月分别四舍五入后求和，与汇总表整季度统一计提金额之间天然存在 $\pm 0.01 \sim 0.05$ 元的不可约分角尾差。

### 2. 财务合规处理原则
遵循《企业会计准则》及工程研发费用核算常规，分摊尾差**必须且只能在季度最后一个月（第 3 个月）进行平账抹平**，绝不破坏前两个月的正常折算逻辑。

### 3. 公式级平账方案（自动与手动）
- **自动平账引擎（内置）**：
  `batch_allocator.py` 在构建每季度第 3 个月分摊表时，自动预演每人 3 个月累积分摊额与法定目标金额的尾差：
  $$\Delta_i = R_i^{\text{target}} - \sum_{m=1}^3 \text{Alloc}_{i, m}^{\text{sim}}$$
  当 $|\Delta_i| \le 1.0$ 元时，自动将第 3 个月的【1.研发工资】公式改写为：
  ```excel
  =E5*$D5 + 0.02    (或 =E5*$D5 - 0.01)
  ```
- **多级动态联动与 0.00 差额闭合**：
  由于分摊小计列为 `=SUM(O5, P5, V5, W5)`，合计行为 `=SUM(X5:X13)`，研发工资末尾的加减数会被各级汇总公式自动吸收。考勤表打点仍保持标准的 8/4/2/1/0.5 整数及半小时面额，而全季度 3 个月实际计算结果与汇总表法定研究人员费**绝对 100.00% 相等，差额严格恒为 0.00 元**！
- **Excel 手工抹平指引**：
  若在 Excel 中手工调整，只需在季度第 3 个月的分摊表（如 202403月）中，找到目标人员的【1.研发工资】单元格（O列或P列），在原有公式 `=E5*$D5` 末尾直接手动键入 `+0.02` 或 `-0.01`，按回车即可一秒抹平！

## 七、官方定稿模板克隆与版式绝对一致性架构 (Master Template Cloning Architecture)

为杜绝任何表格样式、行高列宽、单元格边框、字体字号与打印分页与人工定稿版产生偏差，引擎采用**基于官方打印定稿模板的原生克隆架构 (`openpyxl.load_workbook`)**：
- **基准模板文件**：`2024年7-9月研发人员薪酬、职工薪酬分配表21-B-02（定稿打印版）.xlsx`。
- **克隆与动态重构流程**：
  1. 深度克隆基准模板中的 6 张工作表（3 张分摊表 + 3 张考勤表）。
  2. 根据实际季度动态重命名 Sheet（如 `202201月`、`202201月考勤表`）。
  3. 保留原表首行主标题、副表头信息、底端审核签名栏及全部行高、列宽、页面横向打印设置（`landscape`，A4 纸张代码 9）。
  4. 动态解绑旧数据行合并单元格并删除旧行，按当季度人员名单重新写入考勤打点、分摊基数与动态公式。
  5. 无论是 `21-B-02`、`极硬岩 (2022-B26)` 还是后续任何其他研发课题，生成的表格均与官方最终打印版具有 **100% 绝对一致的视觉与打印布局规范**。

### 2. 全周期 13 季度零误差 (0.00 元) 穿透核验
生成完毕后，可直接调用 `scripts/verify_project.py` 进行全生命周期自动化对账：
```bash

python scripts/verify_project.py 21-B-02

# 校验极硬岩

```
校验引擎将穿透读取所有生成表格的底层公式与考勤打点，实时重算工时率与各薪酬分摊项，与季度汇总表法定目标总额进行高精度比对。
输出验证指标必须达到：
- **各季度差额**：全部为 **0.00 元**（100% 绝对平衡）。
- **全生命周期累积总差额**：绝对值 **< 0.001 元**。
